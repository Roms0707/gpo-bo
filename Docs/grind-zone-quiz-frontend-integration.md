# Grind Zone Quiz - Frontend Integration Guide

## Date
2026-02-20

## Overview

The Grind Zone Quiz system lets users answer a 4-question quiz after watching all videos in a Grind Zone rubric section. Quizzes are AI-generated by admins from video content via the backoffice, then published for end users. This document describes everything the frontend developer needs to wire up the quiz modal, persist answers, and display results.

---

## 1. Database Schema

### Existing Tables (read-only from frontend perspective)

#### `grind_zone_quizzes`
| Column | Type | Description |
|---|---|---|
| id | uuid | Primary key |
| rubric_id | text | Galaxy rubric ID this quiz covers |
| rubric_name | text | Cached rubric display name |
| project_config_id | uuid | FK to project_configurations |
| game_id | uuid | Optional FK to games |
| title | text | Quiz title |
| status | text | `draft` or `published` (only show `published` to users) |
| language | text | `en`, `fr`, or `es` |
| video_count | integer | Number of videos analyzed to generate the quiz |
| created_at | timestamptz | Creation timestamp |

#### `grind_zone_quiz_questions`
| Column | Type | Description |
|---|---|---|
| id | uuid | Primary key |
| quiz_id | uuid | FK to grind_zone_quizzes (CASCADE delete) |
| question_text | text | The question |
| question_type | text | `multiple_choice`, `true_false`, or `open_ended` |
| options | jsonb | Array of option strings (e.g., `["A","B","C","D"]`) for MC/TF; `null` for open_ended |
| correct_answer_index | integer | Index into `options` for the correct answer (MC/TF only) |
| correct_answer_text | text | Expected answer text (open_ended only) |
| explanation | text | Why the correct answer is correct |
| display_order | integer | 1-4, ordering within the quiz |

### New Table: `grind_zone_quiz_submissions`
| Column | Type | Description |
|---|---|---|
| id | uuid | Primary key |
| user_id | uuid | FK to auth.users (the user taking the quiz) |
| quiz_id | uuid | FK to grind_zone_quizzes |
| score | integer | Number of correct auto-gradable answers (MC + TF only) |
| total_questions | integer | Total questions in the quiz (always 4) |
| is_completed | boolean | `false` while in progress, `true` when all questions answered |
| answers | jsonb | Array of `QuizAnswerEntry` objects (see below) |
| started_at | timestamptz | When the user first opened the quiz modal |
| completed_at | timestamptz | When all questions were answered; `null` if incomplete |
| created_at | timestamptz | Row creation time |
| updated_at | timestamptz | Last update time |

**Constraint:** `UNIQUE(user_id, quiz_id)` - one submission per user per quiz, supports upsert for partial saves.

**RLS:** Users can only SELECT, INSERT, and UPDATE their own rows (where `auth.uid() = user_id`). No DELETE policy.

```typescript
interface QuizAnswerEntry {
  question_id: string;        // UUID of the grind_zone_quiz_questions row
  question_type: QuestionType; // 'multiple_choice' | 'true_false' | 'open_ended'
  selected_option_index: number | null; // index into question.options (MC/TF); null for open_ended
  answer_text: string | null;           // free-text answer (open_ended); null for MC/TF
  is_correct: boolean;                  // auto-graded for MC/TF; always false for open_ended
}
```

## 3. Service Layer

All submission operations are in `src/services/grindZoneQuizSubmissionService.ts`:

| Function | Parameters | Returns | Description |
|---|---|---|---|
| `startQuizAttempt` | `userId, quizId, totalQuestions` | `{ data, error }` | Creates a new submission row (or no-ops if one already exists via upsert with `ignoreDuplicates: true`). Call this when the modal opens. |
| `savePartialProgress` | `userId, quizId, answers[]` | `{ error }` | Updates the `answers` jsonb and recalculates score. Call this when the user closes the modal mid-quiz. |
| `completeQuiz` | `userId, quizId, answers[]` | `{ data, error }` | Sets `is_completed = true`, `completed_at = now()`, final answers and score. Call this after the last question is answered. |
| `fetchUserSubmission` | `userId, quizId` | `{ data, error }` | Gets the existing submission for resume or showing results. Returns `null` if none exists. |
| `fetchUserSubmissions` | `userId, quizIds?` | `{ data, error }` | Gets all submissions for a user, optionally filtered by quiz IDs. |
| `hasCompletedQuiz` | `userId, quizId` | `{ completed, error }` | Quick boolean check. |

To fetch a quiz with its questions, use the existing service:
```typescript
import { fetchQuizWithQuestions } from '../services/grindZoneQuizService';
```

## 4. Quiz Structure (Fixed 4-Question Pattern)

Every quiz has exactly 4 questions in this order:

| # | Type | Options | Auto-graded? |
|---|---|---|---|
| 1 | `multiple_choice` | 4 options | Yes |
| 2 | `multiple_choice` | 4 options | Yes |
| 3 | `true_false` | 2 options (True/False or localized equivalent) | Yes |
| 4 | `open_ended` | None (free-text input) | No |

**Maximum auto-gradable score: 3** (questions 1-3). The open-ended question is informational - store the user's text and show the reference answer after submission.

## 5. Modal Trigger Logic

The quiz modal should pop up automatically after the user finishes watching all videos in a Grind Zone rubric section. Here is the exact logic:

### Step-by-step trigger flow

1. **Track video completion** using the existing `user_video_progress` table. A video is "completed" when `is_completed = true` (set automatically when >90% of the video has been watched).

2. **Count progress per rubric:** Compare how many videos exist in the rubric vs. how many the user has completed.

   ```typescript
   // Get all content_ids for videos in this rubric
   // (this depends on how Galaxy content is mapped to rubric_id in your frontend)
   const totalVideosInRubric = rubricVideos.length;

   // Count completed ones from user_video_progress
   const { data: progress } = await supabase
     .from('user_video_progress')
     .select('content_id')
     .eq('user_id', userId)
     .eq('is_completed', true)
     .in('content_id', rubricVideoContentIds);

   const completedCount = progress?.length || 0;
   const allVideosWatched = completedCount >= totalVideosInRubric;
   ```

3. **Check if a published quiz exists for this rubric:**
   ```typescript
   const { data: quizzes } = await supabase
     .from('grind_zone_quizzes')
     .select('id')
     .eq('rubric_id', rubricId)
     .eq('project_config_id', projectConfigId)
     .eq('status', 'published')
     .limit(1);

   const quizAvailable = quizzes && quizzes.length > 0;
   const quizId = quizAvailable ? quizzes[0].id : null;
   ```

4. **Check if the user already completed it:**
   ```typescript
   import { hasCompletedQuiz } from '../services/grindZoneQuizSubmissionService';
   const { completed } = await hasCompletedQuiz(userId, quizId);
   ```

5. **Trigger the modal:**
   ```
   if (allVideosWatched && quizAvailable && !completed) {
     openQuizModal(quizId);
   }
   ```

### When to run this check
- After a video's `is_completed` flag transitions to `true` (i.e., after the video player reports >90% watched)
- When the user navigates to a rubric section where they've previously watched all videos

## 6. Partial Completion / Resume

When the user closes the modal before finishing all 4 questions:

1. **Save progress:** Call `savePartialProgress(userId, quizId, answersCollectedSoFar)`.
2. **On return:** When the trigger condition fires again (all videos watched, quiz available, not completed), call `fetchUserSubmission(userId, quizId)`.
3. **Resume:** If the submission exists and `is_completed === false`, reopen the modal at the first unanswered question. Determine resume position from the `answers` array length:
   ```typescript
   const submission = await fetchUserSubmission(userId, quizId);
   if (submission.data && !submission.data.is_completed) {
     const resumeAtIndex = submission.data.answers.length; // 0-based
     openQuizModal(quizId, { resumeAt: resumeAtIndex, existingAnswers: submission.data.answers });
   }
   ```

## 7. Scoring Logic

### Auto-graded questions (multiple_choice and true_false)

```typescript
function gradeAnswer(
  question: GrindZoneQuizQuestion,
  selectedOptionIndex: number
): boolean {
  return question.correct_answer_index === selectedOptionIndex;
}
```

### Open-ended question
- No auto-grading. Store the user's text in `answer_text`.
- Set `is_correct: false` (convention; not meaningful for open-ended).
- After submission, display the reference answer from `question.correct_answer_text` and the `explanation` so the user can self-assess.

### Building the answers array

```typescript
function buildAnswerEntry(
  question: GrindZoneQuizQuestion,
  selectedOptionIndex: number | null,
  answerText: string | null
): QuizAnswerEntry {
  const isAutoGradable = question.question_type !== 'open_ended';
  const isCorrect = isAutoGradable && selectedOptionIndex !== null
    ? question.correct_answer_index === selectedOptionIndex
    : false;

  return {
    question_id: question.id,
    question_type: question.question_type,
    selected_option_index: selectedOptionIndex,
    answer_text: answerText,
    is_correct: isCorrect,
  };
}
```

### Final score
The service calculates this automatically: count of answers where `question_type !== 'open_ended' && is_correct === true`. Maximum score is 3.

## 8. Post-Quiz Behavior

After the user answers all 4 questions:

1. Call `completeQuiz(userId, quizId, finalAnswers)`.
2. Show a results screen with:
   - Overall score: `X / 3` (auto-gradable questions only)
   - Per-question breakdown: the user's answer, whether it was correct, and the explanation
   - For the open-ended question: the user's text alongside the reference answer and explanation
3. The quiz modal should not re-trigger once `is_completed === true`.

### Optional: Activity Log and XP

If gamification is active, log the completion:

```typescript
// Activity log entry
await supabase.from('activity_log').insert({
  user_id: userId,
  activity_type: 'quiz_completed',
  activity_data: {
    quiz_id: quizId,
    quiz_title: quiz.title,
    score: submission.score,
    total_questions: submission.total_questions,
    rubric_id: quiz.rubric_id,
  },
  xp_earned: 50, // configurable amount
  is_public: true,
});

// XP event entry
await supabase.from('xp_events').insert({
  user_id: userId,
  amount: 50, // same XP amount
  source: 'grind_zone_quiz',
  source_id: quizId,
  source_details: `Completed quiz: ${quiz.title}`,
  metadata: { score: submission.score, total: 3 },
});
```
